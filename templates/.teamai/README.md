# TeamAI Local Memory

TeamAI is a local-first, hook-first MVP for extracting reusable project
knowledge from your normal Claude Code workflow.

Its job is simple:

1. inject mature local knowledge into Claude at the right time
2. request a stop-time summary through a dedicated Claude subagent
3. defer a background session-end summary when that stop-time summary never completes
4. extract candidate knowledge and spec notes automatically
5. promote repeated, higher-confidence patterns into reusable memory
6. compile repo facts plus promoted rules into injectable TeamAI spec artifacts

This is intentionally lightweight. It is not a full team knowledge platform and
not a server-backed collaboration system yet.

## Quick Start

This `.teamai/` directory is generated by the TeamAI Local CLI.

```bash
teamai-local init /path/to/your/repo
```

This does four things:

1. creates the `.teamai/` scaffold
2. adds `.teamai/` to `.gitignore`
3. merges Claude hooks into `.claude/settings.json`
4. installs `.claude/agents/teamai-memory-summarizer.md`

If you run `teamai-local init` again later, choose one of:

- `--skip-existing` to preserve generated TeamAI files
- `--force` to overwrite generated TeamAI files

Re-running `init` also refreshes the managed TeamAI hook entries in
`.claude/settings.json`, so hook command and timeout upgrades can move forward
without duplicating TeamAI's own hooks.

After that, keep using Claude Code normally. TeamAI works in the background.

## How It Works

### 1. Session start injection

When a Claude session starts, resumes, clears, or compacts, TeamAI injects:

- the latest evidence summary
- the latest changed file list
- promoted knowledge from `knowledge/memory.md`
- promoted spec notes from `specs/candidate-spec.md`

TeamAI first compiles structured state into generated artifacts, then injects
those compiled artifacts back into Claude. Candidate items are not injected.

### 2. Tool-call injection

When Claude invokes `Task` or `Agent`, TeamAI prepends the compiled shared
context so delegated sub-agents inherit the local project memory.

Empty placeholder lines such as `No promoted entries yet.` are not injected back
into prompts.

### 3. Stop-time summary capture

When Claude tries to stop, TeamAI can block once and ask the main model to run
the `teamai-memory-summarizer` project subagent.

That path works like this:

1. `Stop` decides whether the latest assistant reply is worth summarizing
2. if yes, it returns `decision: block` with instructions to launch the
   `teamai-memory-summarizer` subagent exactly once
3. `SubagentStart` injects the shared TeamAI context plus the active summary
   request details
4. the subagent returns strict JSON with `summary`, `knowledge`, and
   `candidate_spec`
5. `SubagentStop` parses that JSON, grades the evidence, and persists it

This keeps the summarization step inside the same Claude session instead of
starting a separate `claude -p` process.

### 4. Session-end fallback

When the session ends without a completed stop summary, TeamAI starts an async
background worker that first tries to finish a deferred summary from the saved
stop-request context. If that context is unavailable, it records fallback
evidence so the session is not lost.

The session-end path:

1. records a session-end event
2. reuses the saved stop-summary request when one exists
3. reads the transcript tail if available
4. uses the captured changed-file and diff snapshot
5. writes either a deferred summary payload or a deterministic fallback summary
6. grades the evidence quality
7. merges extracted bullets into the local merge index when eligible
8. writes updated memory/spec artifacts
9. writes an outbox envelope for future sync when `sync.enabled` is true

## Learning Model

TeamAI uses a small promotion model instead of a full knowledge workflow engine.
The rule store is structured JSON; Markdown files are generated views.

Each extracted bullet is stored with:

- a normalized fingerprint
- canonical text
- a typed `kind`
- a `scope`
- matched `paths`
- inferred repo/tool requirements
- source evidence ids
- first seen / last seen timestamps
- occurrence count
- evidence count
- best grade and score
- average score
- confidence
- promotion status
- lifecycle status

When repo facts drift, TeamAI can invalidate a previously promoted rule and
demote it out of future prompt injection until the repo matches again.

### Promotion rule

By default, an entry is promoted only if all of the following are true:

- it appeared at least `2` times
- it has at least `2` evidence events
- its confidence is at least `0.68`

This prevents one noisy session from immediately polluting future prompts.

## Evidence Quality

Each session gets a quality score and grade:

- `A`
- `B`
- `C`
- `D`

The score is based on signals such as:

- transcript presence
- diff presence
- changed files
- whether a model-generated summary was available
- whether useful knowledge/spec items were extracted

By default, only evidence with grade `C` or better is eligible for merge.

Internal tool-managed paths are excluded from evidence by default:

- `.teamai/`
- `.omc/`
- `.claude/`
- `.git/`

Stop-time and session-end events snapshot changed files and diff state at event
creation time, so later worktree changes do not rewrite the evidence for the
original session.

Untracked files are included in the captured worktree diff summary so
new-file-heavy sessions are not scored as "no diff".

## Directory Layout

### Core files

- `config.json` - local runtime configuration
- `hooks/common.py` - shared helpers
- `hooks/pipeline.py` - shared extraction and summary-state logic
- `hooks/session_start.py` - SessionStart context injection
- `hooks/pre_tool_use.py` - Task/Agent prompt injection
- `hooks/stop.py` - Stop hook gate for TeamAI summary requests
- `hooks/subagent_start.py` - summary subagent context injection
- `hooks/subagent_stop.py` - strict JSON capture and persistence
- `hooks/session_end.py` - async session-end fallback worker

### State and artifacts

- `evidence/latest.json` - most recent extracted evidence
- `evidence/sessions/*.json` - per-session evidence snapshots
- `knowledge/memory.md` - promoted and candidate shared knowledge
- `specs/candidate-spec.md` - promoted and candidate spec notes
- `state/merge-index.json` - canonical merge and promotion state
- `state/compiled-state.json` - compile-cache fingerprint for generated artifacts
- `state/repo-profile.json` - scanned repository background facts
- `state/rule-store.json` - structured TeamAI rule store
- `state/session-events/*.json` - pending worker events
- `generated/spec.md` - compiled reusable TeamAI spec
- `generated/inject/session-start.txt` - compiled SessionStart injection
- `generated/inject/tool-task.txt` - compiled Task/Agent injection
- `generated/inject/subagent.txt` - compiled SubagentStart injection
- `logs/session-end.log` - background worker log

### Sync skeleton

- `sync/outbox/*.json` - upload-ready protocol envelopes
- `sync/protocol.md` - local-to-server protocol contract

### Project subagent

- `.claude/agents/teamai-memory-summarizer.md` - strict JSON summarizer used by
  the Stop flow

## Reading the Artifacts

### `knowledge/memory.md`

This file contains:

- `Promotion Rules`
- `Promoted Entries`
- `Candidate Queue`
- `Invalidated Entries`

Promoted entries are the only entries that get injected.

Each rendered item includes compact metadata:

```text
[B|78|x2|c0.76|workflow|repo] TeamAI should only inject promoted entries back into context.
```

Meaning:

- `B` - best grade seen so far
- `78` - best score
- `x2` - occurrence count
- `c0.76` - current confidence
- `workflow` - inferred rule kind
- `repo` - inferred rule scope

### `specs/candidate-spec.md`

Same structure as memory, but intended for reusable workflows, conventions, and
candidate contracts.

### `evidence/latest.json`

Useful when you want to inspect what TeamAI just learned from the last session:

- summary
- files
- generator
- quality
- extracted knowledge
- extracted candidate spec bullets
- merge stats

## Configuration

Main configuration lives in `config.json`.

All configurable artifact and outbox paths must stay inside `.teamai/`. TeamAI
rejects path traversal or absolute-path escapes instead of writing outside its
managed runtime directory.

### Stop summary

```json
"stopSummary": {
  "enabled": true,
  "minimumAssistantChars": 450,
  "minimumChangedFiles": 1,
  "allowWithoutChanges": true,
  "maxBlockAttempts": 2
}
```

Notes:

- `enabled` controls whether the Stop hook asks for a summary
- the summary subagent name is fixed as `teamai-memory-summarizer`
- `minimumAssistantChars` avoids blocking on trivial responses
- `minimumChangedFiles` lets file activity trigger a summary even with a shorter reply
- `allowWithoutChanges` lets long assistant replies trigger summaries even when the
  worktree is clean
- `maxBlockAttempts` prevents repeated stop loops if the subagent never completes

### Capture filters

```json
"capture": {
  "excludePathPrefixes": [
    ".teamai/",
    ".omc/",
    ".claude/",
    ".git/"
  ]
}
```

Use this to exclude tool-managed paths from file lists and diff snapshots before
evidence is summarized.

### Merge gate

```json
"merge": {
  "minimumGrade": "C",
  "promotion": {
    "minimumOccurrences": 2,
    "minimumEvidenceCount": 2,
    "minimumConfidence": 0.68
  }
}
```

Use this to make learning stricter or looser.

Examples:

- want faster promotion for solo experiments: lower `minimumOccurrences`
- want safer promotion for noisy repos: raise `minimumConfidence`
- want to reject weaker sessions entirely: raise `minimumGrade` to `B`

## Normal Workflow

You do not need a special workflow.

Use Claude Code normally:

1. start a session
2. inspect files
3. ask questions
4. edit code
5. end the session

TeamAI will gradually learn patterns such as:

- stable project conventions
- reusable local workflows
- recurring architecture notes
- implementation constraints that keep reappearing

## Why This MVP Is Useful

### 1. Zero manual knowledge maintenance

You do not need to stop and write docs every time you discover a reusable
pattern.

### 2. Lower prompt repetition

If you keep re-explaining the same local conventions to Claude, TeamAI can
eventually promote them and inject them automatically.

### 3. Safer than one-shot memory

It does not trust a single extraction. Repetition and confidence are required
before future sessions see the item.

### 4. Local-first and low-risk

All state stays in `.teamai/`, which is ignored by Git by default.

### 5. Good base for future team sync

The outbox and protocol files let you add server sync later without replacing
the local extraction path.

## Current Limits

This MVP does not yet provide:

- shared team database sync
- conflict resolution across multiple developers
- explicit human review workflow
- semantic clustering across near-duplicate bullets
- promotion into official repository specs

It is a local learning layer, not a final knowledge system.

## Troubleshooting

### Nothing gets extracted

Check:

- `.claude/settings.json` contains the TeamAI hooks
- `.teamai/state/summary-state.json` to see pending/running/completed requests
- `.teamai/logs/session-end.log` for worker output
- `.teamai/evidence/latest.json` for the last processed result
- `teamai-local status /path/to/repo` to see pending worker events

### Extraction runs but memory stays empty

Possible causes:

- the summarizer returned no useful items
- evidence grade was below `minimumGrade`
- items are still in the candidate stage and not yet promoted

Check:

- `.teamai/evidence/latest.json`
- `.teamai/state/merge-index.json`
- the `Candidate Queue` sections in memory/spec files

### Promoted items are not being injected

Check:

- the item is under `Promoted Entries`, not `Candidate Queue`
- Claude is actually triggering `SessionStart`
- `CLAUDE_NON_INTERACTIVE=1` is not preventing interactive injection

## Suggested Next Steps

Once this local MVP feels stable, the next logical upgrade is:

1. keep local extraction exactly as-is
2. sync outbox envelopes to a shared service
3. merge repeated patterns across developers on the server side
4. promote high-confidence shared knowledge back down to repositories
